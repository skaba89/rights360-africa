# Tenant isolation (development)
The runtime role is distinct from the migration/bootstrap superuser. RLS on organizations and tenant_modules defaults to no access without a transaction-local tenant context. Never accept a tenant ID directly from an unverified request. The context helper is internal; authentication and membership checks are not yet implemented. RLS is defense in depth, not a protection against arbitrary SQL execution as the runtime role, which can change its own context. No production use before least-privilege migration role, credential rotation, authenticated membership, and verified integration tests.
