# MFA recovery
Enrollment confirmation now returns ten random 128-bit recovery codes, displayed once. Store them securely offline; only SHA-256 hashes are stored. Login requires the password plus either a fresh TOTP or one recovery code. Recovery codes are consumed atomically in the same transaction as session creation and cannot be reused. Regeneration at POST /api/v1/auth/mfa/recovery/regenerate requires a valid session, password and fresh TOTP, and invalidates all prior codes. Existing MFA users can use this endpoint to generate their first set.
A recovery code does not disable MFA or reset a lost authenticator. A separate controlled recovery procedure, mandatory administrator MFA, audit and user-facing enrollment flows remain required before production. Never log recovery codes or API response bodies containing them.
