# Royalty billing baseline
Administrators issue internal receivables by recalculating an explicit tariff version against an active matching exploitation license. Both finance and licenses modules must be enabled for issuance. One receivable per license and usage date is allowed; this deliberately conservative rule needs richer billing periods and usage identifiers later. References are unique per institution. Receipts are manual declarations of funds received, not transfers or verified bank transactions. Transaction advisory locks and a database trigger reject overpayment; duplicate receipt references are rejected. Invoices and receipts are append-only for the runtime role. Balances and payment status are computed from receipts. Managers and auditors read only. All money is in integer minor units; API amounts are serialized as strings. No tax, fiscal numbering, PDF invoice, credit note, reversal, reconciliation, reminders, independent approval, or verified payment integration yet. Browser E2E, concurrency/load tests and production review remain outstanding. Do not use for legally issued invoices until local requirements are validated.
