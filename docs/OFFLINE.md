# Field offline vault
The static portal shell is cached by an allowlisted service worker; authenticated API responses and bearer tokens are never cached by that worker. IndexedDB stores an AES-256-GCM encrypted draft queue with random IV, account/organization-scoped associated data and a PBKDF2-SHA256 key derived from a separate passphrase (600000 iterations). Revision checks within a read/write transaction reject stale writes. The portal requires online authentication to reopen a vault after reload or logout. A user can continue capturing while the active session remains valid, but cannot start a new authenticated session fully offline. Use a strong unique passphrase and a managed device; losing the passphrase or clearing browser storage can permanently lose unsynchronized drafts. Browser storage can be evicted. No remote wipe, background synchronization, conflict merging, passphrase recovery, full offline authentication or protection against compromised browser scripts is provided. Tests exercise actual Chromium cryptography, persistence, revision conflicts, wrong passphrase, account scope and offline shell/API boundary with synthetic data. They do not constitute end-to-end authenticated field workflow or Android/iOS qualification. No production deployment.
