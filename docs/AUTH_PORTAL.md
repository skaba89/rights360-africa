# Authentication portal
Open /portal on the same origin as the API. The first responsive portal uses plain HTML, CSS and JavaScript to avoid adding a second service before the functional workflow is validated. It supports login with organization UUID, TOTP or recovery code, both invitation acceptance flows, MFA enrollment and recovery code display, identity and logout. Bearer tokens are held only in JavaScript memory; refreshing requires a new login. No third-party assets. CSP and no-store headers are applied to portal resources.
The portal is a development baseline, not a production authorization. Browser end-to-end testing, accessible usability review, secure cookie/BFF architecture evaluation, automated invitation delivery, password recovery, platform console and business dashboards remain outstanding. The backend remains the authority for permissions.
